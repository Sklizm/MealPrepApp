# MealPrepApp 1.0.0-rc.1

Draft release candidate for the cooking-centred Avalonia redesign. Publication waits for native acceptance. The Windows WPF practica client is retained and compiled in CI; no Windows package is attached.

## Changes

Warm System/Light/Dark themes, responsive sidebar navigation, recipe filters and drafts, serving scaling, cooking mode with a session timer, weekly planning and copy preview, and saved shopping checklists with explicit pantry import. Includes compatibility repairs and database regression coverage.

## Install

Download the archive for your platform plus `SHA256SUMS`. In the download folder verify it with `shasum -a 256 -c SHA256SUMS` on macOS or `sha256sum -c SHA256SUMS` on Linux. If you downloaded only one archive, the other entry will report missing; verify the downloaded entry reports OK.

- **Mac Apple Silicon:** extract `MealPrepApp-macos-arm64.tar.gz`, replace the old `MealPrepApp.app`, then open it. This app is unsigned and unnotarized; native launch/Gatekeeper acceptance remains to be checked.
- **Linux x64:** extract `MealPrepApp-linux-x64.tar.gz` and run `MealPrepApp-linux-x64/MealPrepApp.Desktop`. Requires X11/XWayland and platform graphics libraries. NixOS packaging remains an unvalidated bootstrap; use the documented dev shell for native libraries.

Configure `appsettings.Local.json` separately in the per-user MealPrepApp directory; no deployment credentials are included. See the repository README for locations. Theme preferences and connection settings survive replacing the app.

## Database prerequisite

Requires `20261028_compatibility.sql` followed by `20261028_cooking_redesign.sql`. Codrin reports the SQL suite and both migrations passed from normal SSH. The agent has not independently inspected the live deployment. Do not rerun migrations merely to prepare this draft; use read-only verification and functional checks first. Existing deployments must follow the documented verified-backup-first update process if an update is needed.

## Verification status

The draft workflow requires standard xUnit across three operating systems, WPF compilation, isolated SQL regressions, contrast checks, updater tests and archive validation. Its run link is appended below when the draft is created; test logs remain Actions artifacts.

Native Mac/Hyprland acceptance and downloaded-package launch checks remain pending until recorded in the release evidence. Headless renders and successful compilation do not establish native acceptance. Closing the app or signing out stops cooking timers. Purchase checks do not alter stock. Compatible units alone are normalized.
