# MealPrepApp 1.0.0-rc.2

Release candidate for Windows x64, Linux x64, macOS Apple Silicon, and the Android
Shopping and Pantry companion. The Android app has its own version, 1.0.1 (code 2).

## Changes

- Purchase batches with optional purchase and expiry dates, quantity-aware recipe
  readiness, reviewed shopping purchases, and explicit pantry imports and corrections.
- Shared planned cooking batches, reusable week templates, ingredient deduction
  review, prepared portions, leftovers, and recorded waste.
- Numbered cooking steps, several named timers, local recipe recovery drafts, and
  reviewed recipe imports from pasted text or supported HTTPS pages.
- Searchable ingredient categories, nutrition editing, and reports for planned,
  cooked, consumed, and discarded activity.
- Native Android Shopping and Pantry with offline shopping edits, retained pending
  operations, explicit conflict review, expiry reminders, and three languages/themes.
- Private authenticated companion API with account ownership, version checks,
  idempotent mutations, and individually revocable device sessions.
- Updated desktop dialogs, Linux X11 session dependencies, API CI build setup, and
  explicit Android SDK package installation in CI.

## Downloads

Download the package for your platform and compare its SHA-256 with `SHA256SUMS`.

| Platform | File | Installation |
|---|---|---|
| Windows x64 | `MealPrepApp-1.0.0-rc.2-windows-x64-setup.exe` | Run the per-user installer. |
| Linux x64 | `MealPrepApp-linux-x64.tar.gz` | Extract and run `MealPrepApp-linux-x64/MealPrepApp.Desktop`. |
| macOS Apple Silicon | `MealPrepApp-macos-arm64.tar.gz` | Extract and move `MealPrepApp.app` to Applications. |
| Android 8+ | `MealPrepApp-Android-1.0.1.apk` | Install the signed APK; updates require the same signing identity. |

Desktop packages include the .NET runtime. Windows packages are unsigned and macOS
packages are unsigned and unnotarized. Linux requires native graphics libraries;
NixOS users should follow the repository's Nix guide.

Desktop requires a reachable SQL Server database and first-launch connection settings.
Android uses the same application account through a separately configured private
HTTPS API. It contains no SQL credentials. Offline use covers cached pantry data
and shopping edits; imports and stock corrections require connectivity.

## Database and upgrades

Apply all ordered migrations in `release.json`, through `20261111_companion.sql`.
Use the verified-backup-first updater for existing deployments. Installers never
provision or migrate SQL Server. Keep desktop user settings and the API token key
across upgrades, and preserve the Android release-signing identity.

## Verification and acceptance

Release packaging requires a successful Compatibility run for the selected commit
and matching desktop package metadata. Android metadata identifies its original
build commit and verifies that its Android source tree matches the selected release.

CI covers desktop tests, WPF compilation, packaging and Windows installation checks,
disposable SQL/API checks, Android JVM tests, lint, and APK assembly. Android device
tests are separate. Physical-phone behavior, native desktop interactions, and
upgrades on each target device still require acceptance; retain this candidate in
draft until the required checks are recorded.

See the [installation guides](https://github.com/Sklizm/MealPrepApp#install-and-run),
[Android guide](https://github.com/Sklizm/MealPrepApp/blob/main/docs/companion/ANDROID.md),
and [release procedure](https://github.com/Sklizm/MealPrepApp/blob/main/docs/releases/README.md).
